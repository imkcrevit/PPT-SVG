# 流程图生成 · 回归测试用例

模型输出是非确定的(ID、措辞、数量每次都会变),所以本套测试**不做 JSON 精确比对**,而是对生成的语义图 + 编译后的几何图做**结构断言**。可运行的断言在 `diagram-regression.ts`,本文件是人类可读的对照说明。

## 怎么跑

把你的"模型调用 + 校验 + 编译"接成一个函数,喂给 `runRegression`:

```ts
import { runRegression } from "./diagram-regression";
import { layoutDiagram } from "@/lib/layout-engine";
import { validateAndNormalizeSemanticDiagram } from "@/lib/semantic-validation";

await runRegression(async (prompt) => {
  const raw = await callYourModel(prompt);        // 返回 JSON 字符串
  const value = JSON.parse(raw);
  const validation = validateAndNormalizeSemanticDiagram(value, "freeform", "zh");
  if (!validation.ok || !validation.diagram) throw new Error(validation.errors.join("; "));
  return { diagram: validation.diagram, figure: layoutDiagram(validation.diagram) };
});
```

每条测试的断言返回失败项数组,空数组 = 通过。所有测试都先跑两条共享断言:
**① 容器包含**(每个有 `parent` 的节点,其盒子必须落在父盒子内——丢锚点的核心回归);
**② 不出画布**(所有盒子在 1280×720 内)。

---

## T1 · 嵌套 + 跨层连接保持锚点(最核心)

- 测试词:`画一个架构图：A 系统下面有子系统 B 和子系统 C，其中子系统 B 调用了外部的 D 系统。`
- 考点:跨容器边界连线时,内层节点是否还稳在父容器里。
- 通过:容器包含全过;存在跨边界的边(B→D);至少一个容器含子节点。
- 建议:换措辞、加干扰句反复跑几次,专测锚点稳定性。

## T2 · 密集信息拆成嵌套节点(图 2 回归)

- 测试词:`生成一个建筑项目从设计到交付的流程图，要求超过 20 个步骤，按前期准备、设计深化、报审采购、施工交付四个阶段分组，每个阶段列出具体的子步骤。`
- 考点:子步骤是否拆成独立嵌套节点,而非塞进一个框的长文字;是否兑现 20+。
- 通过:叶子节点 ≥ 20;≥3 个阶段容器各带多个子节点;**没有任何 label 像"01… 02… / 逗号列表"那样被塞成一串**。

## T3 · 多带 + 自主虚线反馈 + 说明文字(参考图级别)

- 测试词:`画一个 RAG + 多 Agent 的代码生成流水线架构图：离线训练阶段（数据采集、清洗、Embedding、知识库）；在线检索阶段（用户提问、改写 Agent、向量检索、重排、打分）；代码生成阶段（生成、幻觉校验、参数确认），其中幻觉校验失败要重写；最后是执行与工具固化阶段，成功的工具下次可直接复用。`
- 考点:按内容分多带、节点带 `detail`、反馈回路是否被自主标成虚线。
- 通过:`layers` ≥ 3;≥1 条 `dashed` 边;多个节点带 detail;存在一条**回流到更早节点**的虚线边。

## T4 · 说明文字长度自适应(不强制两行)

- 测试词:`画三个步骤：登录、处理、完成。其中"处理"这一步补充说明"调用支付网关、校验库存、写入订单，失败自动重试三次"；另外两步不需要说明。`
- 考点:有说明的撑开、没说明的保持单行,不被强行补成两行。
- 通过:至少一个节点有 detail、至少一个没有(混合存在)。

## T5 · 三层嵌套保持包含

- 测试词:`画一个系统架构：电商平台包含订单中心和用户中心；订单中心里又包含下单服务、支付服务、退款服务；用户中心包含认证和会员两个模块。`
- 考点:平台 > 中心 > 服务三层是否层层包住。
- 通过:嵌套深度 ≥ 2;容器包含全过。

## T6 · 虚线节点(外部 / 暂定)

- 测试词:`画一个数据处理流程，入口是"外部数据源"（用虚线表示这是外部不可控的），然后经过采集、清洗、入库；其中"实时同步"模块是规划中尚未实现的，也用虚线标出。`
- 考点:`node.dashed` 是否被自主用于外部 / 暂定节点。
- 通过:≥1 个 `dashed` 节点。

## T7 · 纯流程无嵌套(逐步配色)

- 测试词:`画一个五步走的产品上线流程：需求评审 → 设计 → 开发 → 测试 → 发布，横向排列。`
- 考点:无 `layers` 时每个顶层步骤一色;链式直连。
- 通过:顶层步骤 ≥ 4;边数 ≥ 步数-1(成链)。

## T8 · 规模压力(缩放兜底)

- 测试词:`画一个企业中台架构图，包含 6 个业务域，每个业务域下面 4~6 个微服务，总共三四十个节点。`
- 考点:接近 40 节点时整图缩放、字号联动、不溢出、容器仍正确包裹。
- 通过:节点 ≥ 25;≥4 个业务域容器;全部在画布内;容器包含全过。

## 判定失败时怎么定位

- 失败信息含 `ANCHOR LOST` → 编译器的容器计算或边路由问题,查 `layout-engine.ts`。
- 失败信息含 `crammed list` / 数量不足 / 缺 dashed → 模型没按规则生成语义图,查并加强对应提示词(`figure-json-contract.md` / 对应 skill)。
- 失败信息含 `exceeds canvas` → 缩放或测量问题,查 `layout-engine.ts` 的 `measure` / `scale`。

T2 和 T3 是这次改动最该盯的回归点,建议每次改完都跑。
